# 增长体验七项改进：实现与验收

日期：2026-09-21｜范围：2026-09-20 审核确认的七项高价值改进。

## 最终行为

1. **手动天气成为明确的来源选择。** 手动填写会记录来源与填写时间，刷新不会被 API 覆盖；只有用户点击“恢复实时天气”才切回自动天气。较早的手填值保留并提示更新，不会静默换源。
2. **调整与采纳按场景记忆。** 在家、出门、睡觉分别保存调整、采纳、当时结果与条件签名。室外变化只使出门记录失效；室温变化只影响在家和睡觉；年龄段、体质、易出汗状态或日期变化会让相关结果重新生成。调整会取消旧采纳，“恢复推荐”也会立即持久化。
3. **首次使用一屏得到价值。** 用户先选在家、出门或睡觉，再确认该场景需要的温度与年龄段。年龄段没有默认选中，生日不再必填；选择哪个场景，结果页就直接打开哪个场景。出门温度留空不会被误判为 0℃。
4. **结果依据透明。** 页面显示本场景相关温度、确认/更新时间、年龄段及天气来源。历史默认室温标为“待确认”，不能直接记下或分享。未设置城市时，在家和睡觉仍可用；出门显示明确空状态并要求填写室外温度。
5. **主操作收敛，帮助留在上下文。** 每个结果只有一个“记下这套搭配”主操作。衣物帮助直接在当前页展示与当前场景、厚度档位相符的真实商品图片与说明，并解释“/”代表替代选择；关闭后原搭配和调整不丢失。
6. **分享当前场景快照。** 好友分享和日期图片分开。快照只包含当前场景、实际结果、日期、相关温度、来源和非敏感年龄段，并校验版本、范围、字段、长度和 48 小时时效。室内分享不依赖城市或室外天气。接收者先读只读卡片，再选择按自己情况生成；快照不写入接收者资料。
7. **回访承接到上次场景。** 条件未变时回到上次场景，并恢复该场景的调整和采纳；条件或日期变化时清楚说明已重新生成，不盲目沿用旧建议。

## 自动化验证

`npm run check` 全部通过：64 个行为测试，项目结构校验为 7 个页面、5 个组件。`git diff --check` 通过。

新增覆盖包括：按场景失效、跨日失效、体质变化、室内无城市分享、年龄段随分享、全部场景/厚度的衣物图例、首次选择场景、出门空温度、调整取消采纳、恢复推荐跨回访保持，以及手动 30℃不被自动天气覆盖。

## 微信开发者工具实测

- 新用户一屏内完成场景、温度、年龄段；选择“睡觉”后结果页实际进入“睡觉”。
- 无城市时确认室温后可以生成睡觉分享；接收页正确显示日期、室温、年龄段和当时搭配。
- 当前“薄睡袋 / 4 层纱布睡袋”打开的图例为现有 4 层纱布睡袋图片，关闭后仍在原搭配。
- 手动输入 30℃返回结果页后，来源和值分别为 `manual`、`30`。
- 出门建议调厚后，旧采纳变为 false；重新记下并切换页面后恢复为调整 `+1`、采纳 true；恢复推荐后重新进入保持 `0`、false。
- 模拟器控制台未发现运行错误。
